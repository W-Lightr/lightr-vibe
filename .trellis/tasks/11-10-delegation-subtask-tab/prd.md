# 子任务统一委派与右侧栏子任务页签

## Goal

让 Lightr 内的子任务尽可能统一走 `delegate_to_agent`（本期只做 MCP 工具描述引导，不改引擎侧配置），
并在右侧栏提供可回看的「子任务」页签：列表以卡片展示每个子任务的基础信息，点击卡片进入子会话详情，可返回列表。

## Background

- 当前模型会优先使用引擎自带的子代理工具（opencode `task` / `subagent_type: "Explore"`），
  该路径不经过 Lightr broker，因此没有 `delegation://started`、没有委派卡、也没有右侧子会话面板。
- 现有右侧栏只有「文件 / 变更 / 详情」三个页签；子代理详情会整块替换右栏，
  打开后无法回看页签，也没有子任务列表。

## Requirements

### R1 · 统一委派引导

- 修改 `delegate_to_agent` 的 MCP 工具描述：明确它是本应用内子任务的唯一受支持入口，
  并要求模型不要使用引擎自带的子代理 / task 工具（否则用户看不到子任务进度）。
- `get_delegation_status` / `cancel_delegation` 的描述需要说明它们操作的是
  `delegate_to_agent` 创建的子任务。
- 对 `claude_code` 会话，额外在 `session/new` / `session/load` 的
  `_meta.systemPrompt.append` 中追加同样的引导（Claude Code 适配器支持的会话级系统提示，
  不改用户全局 `~/.claude` 配置）。实测仅靠工具描述时，Claude 仍会选用原生 `Agent` 工具。
- 本期不修改引擎启动参数、不写引擎配置文件、不屏蔽原生工具（不改 `disallowedTools` /
  `tools.task`）。

### R2 · 「子任务」页签可见性

- 右侧栏页签顺序为「文件 / 变更 / 详情 / 子任务」。
- 仅当当前活动会话存在子任务记录（`parentSessionId === 当前会话 id`），
  或正在查看某个子任务详情时，才显示「子任务」页签。
- 页签文字带数量徽标（例如「子任务 2」）。

### R3 · 子任务列表

- 列表按创建时间倒序，**每个子任务一张卡片**。
- 卡片基础信息至少包含：状态（运行中 / 等待授权 / 等待回答 / 已完成 / 失败 / 已取消 / 已中断）、
  执行的引擎、任务摘要（单行截断，悬停显示全文）、耗时、短任务 id。
- 没有子任务时页签不出现；列表为空但页签被保留时显示空态文案。

### R4 · 详情与返回

- 点击卡片进入该子任务的子会话详情，展示完整对话与子代理的权限 / 提问交互入口。
- 详情顶部提供「返回」按钮，返回子任务列表；提供关闭按钮，关闭整个右侧栏。
- 返回后停留在「子任务」页签的列表态。

### R5 · 自动打开行为

- `delegation://started` 到达时仍自动打开右侧栏，但落在「子任务」页签并直接展示该子任务的详情。
- 用户手动关闭右侧栏后，再点击顶栏的右栏按钮应回到上次停留的页签。

### R6 · 会话隔离

- 子任务列表与页签计数只统计当前活动会话派生的子任务。
- 切换会话后，若新会话没有子任务且当前不在详情态，页签隐藏并回落到「文件」页签。
- 正在查看详情时切换会话，允许继续查看；返回后落到当前会话的列表（可能为空）。

### R7 · 状态实时性

- 子任务状态随 `delegation://updated` 实时更新（卡片徽标、列表排序保持合理）。
- 应用重启后恢复的历史记录（`interrupted`）同样可列出、可进入详情。

## Acceptance Criteria

- [ ] AC1：开启「子代理委派」并新开会话后，模型使用 `delegate_to_agent` 而不是引擎原生子代理；
      工具描述文本包含「唯一入口 / 不要使用引擎自带子代理」的明确约束。
- [ ] AC2：当前会话无子任务时不显示「子任务」页签；有 1 个或多个时显示，且数量正确。
- [ ] AC3：页签内每个子任务一张卡，卡片展示状态、引擎、任务摘要、耗时、短 id，顺序为创建时间倒序。
- [ ] AC4：点击卡片进入详情，能看到子代理完整对话与权限 / 提问交互区。
- [ ] AC5：详情点「返回」回到列表；点关闭按钮隐藏整个右栏；再次打开右栏仍停留在「子任务」页签。
- [ ] AC6：`delegation://started` 触发时右栏自动切到「子任务」页签并展示该子任务详情。
- [ ] AC7：切换到没有子任务的会话时页签隐藏并回落「文件」；详情态下切换会话不崩溃、可返回。
- [ ] AC8：子任务状态变化（运行中 → 完成 / 失败 / 等待授权）在卡片上实时反映。
- [ ] AC9：浏览器 mock 环境（无 Tauri）下右栏正常渲染，不出现子任务页签也不报错。
- [ ] AC10：`pnpm build` 与 `cargo check`（含 `lightr-ask-mcp` bin）通过；现有会话、权限、提问流程无回归。

## Out of Scope

- 引擎侧禁用原生子代理工具（opencode `tools.task=false`、claude_code `--disallowedTools Task`）。
- 原生子代理调用的兜底识别与「原生子代理」卡片。
- 子任务记录的删除 / 清理 UI、跨项目汇总视图。
- 委派开关默认值调整（保持默认关闭）。
- 子任务嵌套与多级委派。

## Constraints

- 不引入新依赖；复用 `DelegationRecord`、`ConversationView`、`MessageComposer passive`、
  `formatDuration` 等既有实现。
- 不改动委派 wire 契约（Rust ↔ 前端 camelCase 字段）。
- 不破坏既有从委派卡打开子会话的入口。

## Notes

- 工具描述引导是概率性措施，验收以「开启开关 + 新会话」的实测为准；若仍被原生工具抢占，
  后续任务再评估引擎侧禁用方案。
